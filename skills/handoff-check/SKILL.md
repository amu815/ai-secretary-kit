# 引継ぎを具体的にする

受け手が次に何をすべきか判断できる引継ぎメモを作る。「共有した」と「相手が引き受けた」を分ける。連絡や担当変更は実行せず、メモ・確認事項・相談文を下書きする。

## 必要な項目

各案件について、次の情報を整理する。

| 項目 | 記載内容 |
| --- | --- |
| 期限 | 判明した範囲の絶対日付・時刻・タイムゾーン、根拠。時刻不明などの欠落はそのまま示す |
| 急ぐ理由 | 遅れると誰に何が起きるか、期限までに必要な準備や依存関係 |
| 現状 | 完了したこと、残っていること、最後に確認した日時 |
| 次の行動 | 受け手がまず行う具体的な一手、必要な資料の所在・閲覧権限の確認状況 |
| 担当 | 元の担当、引受候補、候補への打診状況、引受済みの人と承諾の根拠 |
| 受領・引受確認期限 | いつまでに返答が必要か。提案日時は提案と明示し、既存の合意と混同しない |
| 返答がない場合 | 次に相談する相手と時点。不明なら要確認にする |

「明日」「至急」をそのまま最終的な期限にしない。依頼発信日時などの基準が不足する場合は期限要確認とし、日時を創作しない。理由の記載がなければ、急ぐ理由も要確認にする。

## 引受状況の判定

送信済み、既読、共有メモへの記載、CC への追加だけでは、引受済みにならない。単なる「見ました」は受領であり、担当として引き受けたという証拠が必要である。返答がない場合も同意と扱わない。

承諾がなければ「引受未確認」とし、引継ぎ完了と結論しない。本人の不在開始と対応期限を比べ、確認が間に合わない場合は、不在前に責任者などへ相談する下書きを作る。相手の予定や負荷を確認せずに割り当てたり、不在中の対応や残業を当然の前提にしたりしない。

## 出力

急ぎ・未引受・期限不明の案件を先に示し、その後に引継ぎ表と未確認事項を並べる。引受を依頼する文には案件、期限、急ぐ理由、次の行動、返答が必要な日時を入れる。日時が未確定なら置換箇所を残して「送信前に確認」と示す。送信・担当確定は人が行う。
