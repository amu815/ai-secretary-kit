# 任意: オフラインでメールの確認用コピーを作る

普段はプロンプトをコピーして使うだけで始められます。この補助ツールは、ターミナルに慣れていて「確認した下書きと、書き出す下書きが同じか」を確かめたい人向けです。Python 3.10 以上だけで動き、追加パッケージ・API キー・ネット接続は不要です。

**メールの送信機能も、メールアプリとの連携もありません。** `release` は、指定した条件を満たす場合だけ、新しいテキストファイルに確認用コピーを書き出します。送信の可否を決めるのは人です。

## 1. 作業用フォルダに下書きを用意する

以下はリポジトリのルートで実行する macOS / Linux 向けの例です。Windows では、Python の起動コマンドを環境に合わせて `py` などに読み替え、ファイル操作はエクスプローラーでも構いません。

```sh
python3 --version
mkdir -p .private
cp examples/mail-draft.json .private/draft.json
```

`.private/draft.json` をテキストエディタで編集します。例は架空の組織・人物と `example.org` のアドレスです。実際の宛先や個人情報を公開用の `examples/` に書き込まないでください。`.private/` は Git の除外対象ですが、これは暗号化ではありません。共有端末やクラウド同期先への保存、ターミナル出力の共有にも注意してください。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `to` | 文字列の配列、1 件以上 | 表示名を付けない宛先アドレス |
| `cc`, `bcc` | 文字列の配列、省略可 | 省略時は `[]`。空の場合も人が確認する |
| `subject` | 空でない文字列 | 件名。改行不可 |
| `body` | 空でない文字列 | 本文。JSON 内の改行は `\n` と書く |
| `attachments` | 文字列の配列 | 添付予定のファイル名のみ。添付なしは `[]` |
| `unresolved` | 文字列の配列 | 未解決事項。すべて解決できた場合だけ `[]` |

`to`・`subject`・`body`・`attachments`・`unresolved` は必須です。未知の項目、重複キー、誤った型、不正な制御文字、宛先や件名の改行を拒否します。宛先は通常の ASCII アドレスに限定しており、一部の正当な特殊形式や国際化アドレスには対応しません。入力は UTF-8 の JSON、最大 1 MiB です。

## 2. 人が全文を読む

```sh
python3 tools/review_gate.py inspect .private/draft.json
```

宛先・Cc・Bcc・件名・添付予定名・本文に続いて、`Content SHA-256` と次の確認項目が表示されます。

- `recipients`: 宛先の相手、To / Cc / Bcc の使い分け、共有してよい情報の範囲。
- `facts`: 氏名、日付、曜日、時刻、期限、数字、約束を元資料と照合。相対表現の「明日」などは必要に応じて具体化する。
- `tone`: 自分の意図との一致、自然な日本語、相手に適した敬語、何を依頼するかの明確さ。
- `attachments`: 実ファイルを開き、内容、版、共有可否を確認。添付しない場合も「なし」が正しいか確認する。

`unresolved` が空でない場合や、`TODO`、`TBD`、`[要確認]`、`未確認`、`{{名前}}`、`○○` などの目印が残る場合は書き出しを止めます。検出は単純な文字パターンなので、見落としも過剰検出もあります。単に目印を消すのではなく、疑問を解決してから文章を直してください。意図的にその語を使う正当な文章でも停止する場合があります。

**エラーがないことは、内容が正しいことや、人の確認が済んだことを意味しません。** このツールは事実関係、日付と曜日の一致、敬語の適切さ、宛先の実在性や権限を判断しません。

## 3. 確認を終えた本人が書き出す

人が上の 4 項目を確認した後、表示された 64 桁の SHA-256 をコピーし、下の `確認した64桁の値` を置き換えて実行します。**この操作を AI に自己承認させないでください。**

```sh
python3 tools/review_gate.py release .private/draft.json \
  --reviewed-sha256 確認した64桁の値 \
  --confirm recipients \
  --confirm facts \
  --confirm tone \
  --confirm attachments \
  --output .private/reviewed-copy.txt
```

4 種類すべてを 1 回ずつ指定する必要があります。既存ファイルは上書きしません。書き直した場合は、再確認後に `reviewed-copy-v2.txt` など新しい名前を指定してください。出力先の親フォルダは先に作成してください。

SHA-256 は JSON のキーの並びやインデントに依存しない内容 ID です。省略された `cc`・`bcc` は空配列として扱います。宛先・件名・本文・添付名などを変更すると ID が変わり、古い ID では書き出せません。変更した下書きはもう一度 `inspect` し、人が全文を再確認してください。

SHA-256 や `--confirm` は、人が確認した証明・電子署名・承認記録にはなりません。確認していない人やプログラムも同じコマンドを実行できます。制御できるのは、このスクリプトを通したテキスト書き出しの条件だけです。メールアプリから直接送信することは止められません。

## 4. メールアプリで最終確認して送信する

書き出したテキストは確認用コピーで、メールファイルではありません。メールアプリで、宛先と件名をそれぞれの欄へ入力し、本文だけを本文欄にコピーします。**Bcc や確認用ヘッダーを本文へまとめて貼り付けないでください。** 実際のファイルを添付し、送信直前にもう一度、宛先・件名・本文・添付を確認します。

添付は名前の一覧しか扱いません。存在確認、内容の読み取り、マルウェア検査、機密情報の検査、ファイルのハッシュ計算は行いません。同じファイル名のまま中身が変わっても、この内容 ID では検知できません。人が送信する実ファイルを開いて確認する必要があります。メールアプリへ転記した後の変更も、このツールでは検知できません。

## 終了コードと動作確認

| 終了コード | 意味 |
| --- | --- |
| `0` | `inspect`: 機械的な停止条件なし。`release`: 確認用コピーの書き出し成功 |
| `2` | 引数・JSON・型・未解決事項・仮置き表現・内容 ID・確認項目に問題あり |
| `3` | ファイル入出力の失敗。既存の出力先、存在しないフォルダ、アクセス権など |

テストは一時フォルダ内で動作し、メールや外部サービスに接続しません。

```sh
python3 -m unittest discover -s tests -p 'test_review_gate.py' -v
```
