# Webガイドを更新する方へ

一般の利用者はWebガイドから始めます。この文書は教材を更新する開発者向けです。

`website/` はHTML・CSS・JavaScriptだけの静的サイトです。サイト内に業務情報を入力する欄はなく、教材をコピーしてChatGPTアプリに渡す構成です。API、データベース、利用者のログイン機能、独自のアクセス解析は実装していません。サイト教材のインストールは不要ですが、ChatGPTアプリの導入とログインは必要です。

## アプリを開く導線

PCの起動リンクには `codex://threads/new` を使います。公式の[Commands / Deep links](https://learn.chatgpt.com/docs/reference/commands#deep-links)では、ChatGPTデスクトップアプリが互換性のため `codex://` を維持し、このリンクで新しいローカルチャットを開くと説明されています。

この公式ページで確認できるのはデスクトップアプリの仕様です。スマートフォンで同じリンクが動くと断定せず、スマホではアプリアイコンから開くよう案内します。PCでもアプリやブラウザの設定によって開かない場合に備え、手動起動の案内を併記します。全端末での強制起動や起動成功を保証する文言は使いません。

本サイトの実装方針は次のとおりです。

- アプリ起動は利用者がボタンを押したときだけ試す。ページを開いた時点では起動しない。
- リンクは `codex://threads/new` のみとし、本文・個人情報・ファイルパスをURLのクエリへ埋め込まない。公式に `prompt` パラメータはあるが、この教材では内容を利用者がコピーして貼り付ける。
- 起動完了を検出した扱いにせず、開かなければアプリアイコンを使うよう案内する。ChatGPTブラウザ版へ自動転送しない。
- 新しい会話で「ChatGPT」→「Work」を選び、モデル設定を確かめてから貼り付けて送信する。[公式の操作手順](https://learn.chatgpt.com/docs/quickstart?setup=app)

起動リンクの動作と、コピーした内容の貼り付け・送信は別の操作です。文面をコピーしただけで送信されたと表示しないでください。

## モデル設定の案内

キットのおすすめはGPT-6 Sol（表示例：6 Sol）・effort Mediumです。GPT-6 SolはChatにないため、初心者の入口もWorkへそろえます。Mediumは計画時の速度と深さを考えた教材側の提案で、公式既定値や最適保証と書かないでください。モデル・推論の設定は入力欄の下からAdvancedを開く流れを案内し、選べる項目はプラン・アプリ・組織設定・提供時期で異なることを添えます。[公式Models](https://learn.chatgpt.com/docs/models)

サイトのボタンや貼り付ける文は、アプリのモデルやeffortを変更しません。起動URLにモデル指定や本文を埋め込まず、モデル表示を本人が確かめる手順にします。設定が見つからなければWork・アカウント・アプリ更新を確認し、課金やアクセス権限の拡張を前提にしません。[モデル設定の教材](model-setup.md)と表示をそろえてください。

`website/assets/chatgpt-work-select.webp` は、公式Work導入動画の入口画像です。モデル選択後の画面とは呼ばず、出典を表示します。公式ページの操作見本を実アプリのスクリーンショットと説明したり、個人の会話・アカウント情報が入った画面を公開したりしないでください。

## 教材を更新する

共通指示と場面別の指示、初回会話の `get-started.md` は `prompts/`、練習は `examples/first-day.md` が元データです。各Markdownの最初の `text` コード枠だけをコピー用の指示として取り出します。編集後はリポジトリのルートで次を実行します。

```sh
python3 tools/build_website_prompts.py
```

`website/prompts.json` が生成されます。Web側のラベルや確認ポイントも、元の教材と意味が一致するか確認してください。

利用者に複数の空欄を埋めさせず、そのまま送信して一問ずつ進む形を保ちます。初回会話は役割と慣れ具合を任意で確認し、資料が既にある場合は省略します。日々の整理は、共有一覧・スクリーンショット・用事一件から開始します。Google連携の案内を載せても、このサイトでGoogleの認証情報や業務データを受け取る機能は追加しません。

次の行動に資料が必要なら、共有してよい範囲の「依頼メール一件」「締切の箇所」など一つに絞って案内します。既存資料の再要求や、資料を求めた直後の完了質問を避けます。許可済みの同じ範囲で同意を取り直さず、AIだけで安全と断言して全資料を集めないようにします。

用事の整理では、最初と進捗更新時に「順番・ID・状態・用事・期限・担当」の全件表を `text` コード枠で示し、完了数と次の一件を添えます。IDを固定し、完了行と後日の用事を残します。状態不明・期限未確認・担当未定・引受確認待ちを勝手に確定せず、返答待ちと担当未定も区別します。文章の添削だけを頼まれた場合は表を必須にしません。

基本はChatGPTの同じ会話で表を更新します。初回にはメモ帳やメモへのコピー保存も案内しますが、保存を作業開始の条件にしません。外部メモへの自動同期はなく、保存する人が最新版へ貼り替えます。新しい会話で再開するときは最新表を渡します。

教材やJavaScriptを更新したら、`index.html` の `app.js`・`styles.css` と `app.js` 内の `prompts.json` の3箇所で配布版クエリ（例：`?v=20261022-board`）をそろえて更新し、通常の再読み込みで新しいデータが届くことを確認してください。

## ローカルで確認する

```sh
python3 -m http.server 4173 --directory website
```

ブラウザで `http://localhost:4173` を開きます。ファイルを直接ダブルクリックすると教材JSONを読み込めない場合があるため、HTTPサーバーを使います。

- 練習文を一度でコピーでき、共通指示と練習データの両方が含まれること。
- 初回会話用の文と、困ったとき・不明なとき・完了を報告するときの返答文をコピーできること。
- 入力がない日常用プロンプトで、時間帯・相談先の一括入力や未接続のメール探索を要求しないこと。
- 用事の材料から暫定の全件表を作り、完了報告では該当行だけを更新し、完了数・更新表・次の一件を返す指示になっていること。
- 並べ替え後もIDが変わらず、追加は未使用のIDとなり、完了行・後日の用事が消えないこと。待ち・後日の行を今取り組む順番に混ぜないこと。
- コピー・保存や用事本体と別の相談だけで本体を完了にせず、完了した範囲が曖昧な場合は一問確認する指示になっていること。
- 4つの用途を切り替えると、表示とコピー対象が一致すること。
- コピー権限がないときも、本文の選択と手動コピーができること。
- PCの起動ボタンが `codex://threads/new` を使い、本文などのクエリを付けないこと。
- 初回のモードがWorkに統一され、GPT-6 Sol・Mediumをアプリ内で選ぶ説明と、モデルを選択済みと誤認させない画像説明があること。
- スマホとアプリが開かない場合に、アイコンからの手動起動手順が読めること。ChatGPTブラウザ版へ自動転送しないこと。
- スマートフォンの幅で文字やボタンが切れず、キーボードでも操作できること。
- 送信前チェックを操作しても、メール送信や外部への投稿が行われないこと。

## 公開版へ反映する

公開用のソースはGitHubで管理し、ホスティングはSitesで行います。GitHubへのpushだけでSitesが更新される構成ではありません。

Sitesの同じプロジェクトを開き、`website/` の配信用ファイルをSites側の `dist/` に同期して、確認済みの版を保存・デプロイします。既存のSite IDと公開範囲を引き継ぎ、新しいSiteを重複作成しないでください。認証情報をソースに保存しないでください。

閲覧範囲はSites側の設定で管理します。一般の読者へ案内する前に、ログインしていない人にも開ける公開範囲になっていることを確認してください。
